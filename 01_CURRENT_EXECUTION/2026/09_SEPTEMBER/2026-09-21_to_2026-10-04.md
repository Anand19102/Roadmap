# 1. THE FIVE-TIER MASTERY SYSTEM

Every topic in this execution plan receives one of five classifications.

| Level                       | Meaning                                        | What you actually do                                                           |
| --------------------------- | ---------------------------------------------- | ------------------------------------------------------------------------------ |
| 🔴 **MASTER**               | Core interview/DSA/backend foundation          | Understand deeply → implement → explain → practice → revisit                   |
| 🟠 **STRONG UNDERSTANDING** | Important supporting knowledge                 | Understand mechanisms and applications → code examples → explain without notes |
| 🟡 **LEARN / USE**          | Practical knowledge needed to work effectively | Learn how to use it correctly; don't obsess over internals                     |
| 🟢 **SKIM**                 | Useful context but low immediate ROI           | Watch/read once, understand the purpose, move on                               |
| ⚪ **SKIP FOR NOW**          | Not currently necessary                        | Do not spend study time on it; it may return later                             |

### Important

**Mastery does NOT mean memorizing everything.**

For 🔴 topics:

> Understand → reproduce → implement → solve → explain → recall later.

For 🟠 topics:

> Understand → implement/use → explain the main idea.

For 🟡 topics:

> Know what it is, when to use it, and how to use it.

For 🟢 topics:

> Understand enough to recognize the concept and continue.

For ⚪ topics:

> Deliberately ignore them for now.

### Mastery target vs current mastery

A topic being classified 🔴 means:

> **This topic is ultimately a mastery target.**

It does **not** mean:

> "You must permanently master this topic within the first two weeks."

By October 4, the expectation is a **strong independent foundation** in the 🔴 topics introduced during this cycle.

True mastery will develop through:

* repeated implementation;
* problem solving;
* spaced revision;
* pattern recognition;
* later interview/application.

# 11. PROBLEM-SOLVING PROTOCOL

For every DSA problem:

## Step 1 — Understand

What exactly is being asked?

## Step 2 — Examples

Create at least one normal example.

## Step 3 — Brute force

Ask:

> What is the obvious solution?

## Step 4 — Complexity

Determine:

* time;
* space.

## Step 5 — Look for constraints

Ask:

* Is the array sorted?
* Is there a monotonic property?
* Is a subarray involved?
* Is a pair involved?
* Is the problem asking for maximum/minimum?
* Can we reduce repeated work?

## Step 6 — Pattern hypothesis

Ask:

> Does this resemble a known technique?

## Step 7 — Attempt independently

Try before watching the solution.

## Step 8 — Learn the solution

Only now use the instructor/editorial.

## Step 9 — Close the solution

Re-code it yourself.

## Step 10 — Explain

Explain:

* approach;
* why it works;
* complexity;
* edge cases.

## Step 11 — Record mistake

If you got stuck, record WHY.
