# 🗺️ PHASES OVERVIEW

> This document defines the major phases of the career-preparation roadmap.
>
> **Important:** Phases overlap. They are not isolated boxes where one subject completely stops before the next begins.

---

# 1. PHASE DESIGN PRINCIPLE

The roadmap follows:

```text
Foundation
    ↓
Integration
    ↓
Application
    ↓
Internship Readiness
    ↓
Advanced Engineering
    ↓
Placement Readiness
```

Each phase has:

* primary objectives,
* secondary objectives,
* supporting subjects,
* projects,
* revision,
* measurable outputs.

---

# 2. PHASE 0 — SETUP & RESTART

## Timing

**September 12–13, 2026**

## Purpose

Prepare the environment and restart the study routine after the interruption caused by illness.

### Tasks

* finalize study environment,
* organize roadmap folders,
* verify Java environment,
* verify Git/GitHub workflow,
* verify IDE/editor,
* organize course resources,
* perform Java refresher,
* review previously learned material,
* prepare execution system.

### Special rule

This is not intended to be an exhausting academic phase.

The purpose is:

> **Restart cleanly rather than attempting to compensate for lost days by overloading the first week.**

# 3. PHASE 1 — JAVA FOUNDATION + HABIT FORMATION

## Approximate period

**Mid-September 2026 → early October 2026**

## Primary goal

Build a reliable Java foundation while establishing a sustainable daily study habit.

### Primary focus

* Java fundamentals
* syntax
* variables
* data types
* operators
* control flow
* methods
* arrays
* strings
* basic problem solving
* basic complexity awareness

### DSA

DSA begins concurrently, but at controlled intensity.

The objective is:

> **Start the DSA habit without making the first weeks overwhelming.**

### Supporting work

* Git/GitHub
* basic SQL introduction when appropriate
* light aptitude exposure only if the weekly load permits

### Success condition

The student should be comfortable writing basic Java programs without constantly referring to syntax.

# 5. PHASE 3 — DSA CONSOLIDATION + SQL + CORE CS

## Approximate period

**November 2026 → January 2027**

## Primary goals

Turn basic DSA knowledge into actual problem-solving ability.

### DSA

Progress into:

* two pointers
* sliding window
* prefix sum
* binary search
* stacks
* linked lists
* trees
* heaps
* intervals
* recursion/backtracking where appropriate

### Pattern recognition

ItsRunTym becomes increasingly important.

The student learns to ask:

> "What pattern does this problem represent?"

rather than:

> "Have I seen this exact question before?"

### SQL

### Core CS

### Aptitude

A controlled aptitude routine is introduced.

# 12. PHASE 10 — COMPANY-SPECIFIC PREPARATION

When placement drives begin, preparation becomes increasingly company-aware.

The MEC placement data already collected will be used to identify:

* recurring recruiters,
* CSE hiring volume,
* likely role types,
* likely technical requirements,
* likely aptitude requirements,
* coding difficulty,
* interview patterns where reliable information is available.

The objective is not to prepare only for one company.

Instead:

```text
General engineering foundation
        ↓
Company category
        ↓
Likely assessment style
        ↓
Targeted revision
```

# 15. PHASE TRANSITION RULE

We do not advance because:

> "The calendar says this phase is over."

We advance when sufficient readiness has been achieved.

A phase can overlap the next one.

For example:

```text
Java foundation
        ↓
DSA begins
        ↓
Java core continues
        ↓
SQL begins
        ↓
Backend begins
```

There is no requirement to "finish Java forever" before starting DSA.

---

# 16. THE GOLDEN PHASE RULE

Every phase must produce something.

Examples:

### Java phase

> Working Java programs.

### DSA phase

> Solved problems + reusable templates + pattern recognition.

### SQL phase

> Working SQL queries.

### Backend phase

> Working APIs.

### Project phase

> Independent software.

### Internship phase

> Resume + applications + interview readiness.

### Placement phase

> Timed performance + interview readiness.

---

# 17. PHASE SUCCESS CRITERIA

A phase is considered successful when:

* its required knowledge has been learned,
* required practice has been completed,
* mistakes have been recorded,
* revision has begun,
* prerequisite knowledge is reliable,
* the output can be demonstrated independently.

This prevents the common trap:

> **"I watched the course, therefore I learned the subject."**
