# 22 — Resume Building Protocol

> **Purpose:** Build the resume progressively throughout the journey rather than writing it one week before placements.

---

# 1. Core Philosophy

The resume is a **living technical record**.

It should reflect actual development.

Therefore:

**Learn → Build → Measure → Document → Update Resume**

---

# 2. No Resume Inflation Rule

Never claim:

* technologies not actually used
* projects not actually built
* algorithms not understood
* exaggerated performance improvements
* fake responsibilities
* copied achievements

Every line must be defensible.

---

# 3. Resume Evolution

The roadmap maintains:

### Version 0 — Baseline

Basic academic/student profile.

### Version 1 — Technical Foundation

Java + DSA + initial projects.

### Version 2 — Backend

Java + Spring Boot + SQL + backend projects.

### Version 3 — Internship

Internship-ready portfolio.

### Version 4 — Placement

Strongest comprehensive version.

### Version 5 — Backend-Focused

Optimized for backend/SDE roles.

### Version 6 — Full-Stack Variant

Used when frontend/full-stack roles are targeted.

---

# 4. Resume Sections

Potential structure:

1. Name/contact
2. Education
3. Technical skills
4. Projects
5. Experience/internships
6. Achievements
7. Certifications where useful
8. Relevant leadership/extracurriculars where useful

Ordering can change depending on strongest evidence.

---

# 5. Skills Section

Skills should be grouped logically.

Example:

### Languages

Java, Python, SQL

### Backend

Spring Boot, REST APIs, JPA/Hibernate

### Databases

PostgreSQL/MySQL etc., based on actual use

### Tools

Git, GitHub, Docker

### Frontend

React, HTML/CSS/JavaScript etc., only when genuinely learned

Do not create a giant technology shopping list.

---

# 6. Project Bullet Protocol

A strong project bullet should communicate:

**Action + Technology + Technical substance + Result**

Weak:

> Built a Spring Boot project.

Better:

> Developed a Spring Boot REST API with PostgreSQL persistence and JWT-based authentication for...

Strong bullets should contain measurable outcomes where legitimate.

Examples of evidence:

* response-time reduction
* number of endpoints
* number of entities
* test coverage
* dataset size
* users simulated
* deployment
* performance improvements

Never fabricate numbers.

---

# 7. Project Description Preparation

For every serious project maintain:

### One-line description

### 2–3 resume bullets

### 30-second explanation

### 2-minute explanation

### 5-minute deep explanation

### Technical deep-dive

This ensures the resume and interview preparation reinforce each other.

---

# 8. STAR Stories

Maintain stories for:

* difficult project
* debugging problem
* failure
* teamwork
* conflict
* leadership
* learning something difficult
* deadline
* improvement
* achievement

Use:

**Situation → Task → Action → Result**

---

# 9. Resume Evidence Bank

Maintain a file containing raw evidence.

Record:

* project metrics
* GitHub links
* deployment links
* technologies
* technical challenges
* achievements
* certifications
* competition results
* internship information
* responsibilities
* measurable outcomes

This prevents trying to reconstruct everything later.

---

# 10. ATS Awareness

Use:

* standard headings
* readable formatting
* relevant keywords
* clear technology names
* simple structure
* consistent dates

Avoid excessive graphics, tables, icons and decorative elements when they reduce parsing reliability.

---

# 11. Role-Specific Resume Variants

Do not maintain dozens of resumes.

Maintain a small controlled set:

### Backend/SDE

Primary.

### Full-stack

Secondary.

### Data/BI

Only when relevant.

Each version should be genuinely tailored.

---

# 12. Resume Review Checklist

Before sending:

### Accuracy

Is every claim true?

### Technical defensibility

Can I explain it?

### Relevance

Does it match the role?

### Evidence

Can I demonstrate the project?

### Language

Are bullets concise?

### Consistency

Are technologies/dates consistent?

### Formatting

Is it clean and readable?

---

# 13. Resume Timing

Do not spend excessive time polishing the resume during the earliest learning phase.

Early effort should go toward:

**Skills → Projects → Evidence**

Resume refinement becomes increasingly important as internship/placement approaches.

---

# 14. Final Resume Principle

Your resume should not be the story you wish were true.

It should be:

> **A compressed representation of what you can actually do.**

The roadmap builds the substance first and the resume captures it continuously.
