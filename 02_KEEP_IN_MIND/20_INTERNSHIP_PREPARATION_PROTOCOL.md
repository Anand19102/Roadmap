# 20 — Internship Preparation Protocol

> **Purpose:** Make the student internship-ready before the relevant MEC recruitment/internship window rather than waiting until applications open.

---

# 1. Internship Objective

The immediate objective is not simply:

> "Get an internship."

It is:

> **Become technically competitive for software-engineering internships that match the Java/backend trajectory.**

Primary target:

**Software Engineering / Backend / General SDE internships**

Secondary possibilities:

* Full-stack
* Cloud/backend
* Data-related roles where reasonable
* General software roles

---

# 2. Internship Readiness Stack

Before serious internship applications, aim to have:

### Technical

* Java fundamentals
* OOP
* DSA fundamentals
* meaningful LeetCode practice
* SQL
* DBMS basics
* OS basics
* CN basics
* Git/GitHub
* Spring Boot fundamentals
* REST APIs
* database integration

### Portfolio

At least:

* small Java project(s)
* backend project(s)
* one serious portfolio project

### Interview

Ability to:

* explain projects
* solve common DSA problems
* answer core CS fundamentals
* write SQL
* explain backend architecture
* communicate clearly

---

# 3. Internship Preparation Does Not Begin When Applications Begin

Preparation is divided into stages.

## Stage A — Foundation

Java + DSA + basic CS

## Stage B — Technical Construction

SQL + Spring Boot + backend

## Stage C — Portfolio

Progressively stronger projects

## Stage D — Interview Readiness

DSA + CS + SQL + project discussion

## Stage E — Application Mode

Applications + company-specific preparation + mocks

---

# 4. Internship Company Data

The MEC internship data is a strategic input.

The roadmap should track:

* companies
* CSE selections
* total selections
* recurring recruiters
* technical roles where identifiable
* likely technical expectations
* internship timing
* conversion potential when information is available

Recurring/relevant companies should receive greater research attention.

Do not assume:

> "Company appeared once → guaranteed future recruiter."

Historical data is evidence, not certainty.

---

# 5. Target Company Categories

Prioritize companies based on:

### Tier A

Strong technical opportunity / strong learning / strong brand / attractive compensation.

### Tier B

Good software-engineering opportunities with realistic probability.

### Tier C

Safety opportunities and broad campus targets.

### Tier D

Company-specific opportunities requiring special preparation.

The exact classification may change as fresh recruitment data appears.

# 8. Project Explanation Protocol

For every serious project, prepare:

1. Problem
2. Why it matters
3. Users
4. Requirements
5. Architecture
6. Technology choices
7. Database design
8. API design
9. Authentication/security
10. Important implementation decisions
11. Challenges
12. Bugs
13. Performance considerations
14. Testing
15. Deployment
16. Future improvements

Never merely memorize a project description.

You must be able to defend it technically.

# 12. Internship Readiness Check

Before the internship window, ask:

### DSA

Can I solve common easy/medium problems without immediately seeing the solution?

### Java

Can I write Java comfortably?

### SQL

Can I solve common interview queries?

### CS

Can I explain major OOP/DBMS/OS/CN concepts?

### Backend

Can I build and explain a REST API?

### Projects

Can I defend every major technical decision?

### Resume

Is every line defensible?

If any answer is "no", that becomes a targeted preparation task.
