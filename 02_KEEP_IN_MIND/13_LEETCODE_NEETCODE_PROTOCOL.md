# 🧩 LEETCODE / NEETCODE PROTOCOL
## DSA Problem-Solving & Pattern Recognition System

---

## 1. PURPOSE

The objective is NOT: *"Complete as many LeetCode problems as possible."*
The objective is: **Develop reliable problem-solving ability and pattern recognition.**

---

## 2. THE LEARNING STACK

DSA preparation uses several layers:
```text
Java
  ↓
DSA Concept
  ↓
Kunal Kushwaha
  ↓
ItsRunTym Pattern Recognition
  ↓
NeetCode Problem Set
  ↓
Independent LeetCode Practice
  ↓
Revision
```
Each resource has a different purpose.

---

## 3. THE PROBLEM-SOLVING PROTOCOL

Every serious problem should follow:
1. Read
2. Understand
3. Restate
4. Identify constraints
5. Think brute force
6. Analyze brute force
7. Identify pattern
8. Derive optimized approach
9. Dry run
10. Code
11. Test
12. Analyze complexity
13. Record mistake
14. Revisit later

---

## 4. CONSTRAINTS AS CLUES

Constraints are clues. Examples:
* `n ≤ 20` may suggest: brute force, backtracking, bitmasking.
* `n ≤ 10^5` usually means: $O(n)$, $O(n \log n)$, optimized data structure.

---

## 5. PATTERN RECOGNITION

Ask: Is this two pointers? sliding window? prefix sum? hashmap? binary search? stack? heap? BFS? DFS? greedy? DP? backtracking? graph algorithm?
This is where ItsRunTym becomes especially important.

---

## 6. SOLUTION BEFORE CODE

Write pseudocode or explain the algorithm verbally. Do not immediately start typing. Write the solution independently. Avoid copying editorial code.

---

## 7. TESTING & COMPLEXITY

**Test:** Normal case, Smallest case, Largest relevant case, Empty/special case, Duplicate values, Negative values, Boundary conditions depending on the problem.
**Complexity:** Every important solution must have Time $O(\dots)$ and Space $O(\dots)$, and I should understand why.

---

## 8. WHEN I GET STUCK

Use this order:
```text
Own thinking → Example tracing → Brute force → Hints → Concept review → Partial solution → Editorial → Re-code independently
```
Do NOT immediately watch the complete solution.

---

## 9. THE "RE-CODE" RULE

If I use an editorial/solution: Close it. Then: Re-code the solution from scratch.
If I cannot: I have not learned it.

---

## 10. MISTAKE LOG

Record:
* **Problem:** Name/link.
* **Pattern:** Which pattern?
* **Mistake:** What went wrong?
* **Correct insight:** What should I have noticed?
* **Complexity:** Time/space.
* **Revisit date:** When should I solve it again?

---

## 11. REVISION SYSTEM

Problems should be revisited when: concept was recently learned, mistake was significant, solution required hints, pattern was not recognized, implementation was forgotten.
Revision should increasingly become: Full solution → Approach only → Pattern recognition → Problem recognition without code.

---

## 12. TARGET & GOLDEN RULE

The ultimate target is not: *"I solved 500 problems."*
It is: *"When I see an unfamiliar problem, I can systematically determine what tools and patterns might solve it."*

**Golden Rule:** Problems are training repetitions. Patterns are the transferable skill. Independent reasoning is the final objective.
