# 🔄 REVISION SYSTEM

> **Purpose:** Ensure knowledge survives beyond the day it was learned.

---

# 1. WHY REVISION EXISTS

The roadmap is long.

Without revision:

```text
Learn → Forget → Relearn
```

With structured revision:

```text
Learn → Recall → Use → Revisit → Retain
```

---

# 2. REVISION IS NOT REWATCHING

Default revision should **not** mean replaying the entire lecture.

Prefer:

```text
Recall
↓
Notes
↓
Code
↓
Problems
↓
Mistake log
```

Rewatch only when genuinely necessary.

---

# 3. REVISION TYPES

## TYPE A — QUICK RECALL

Ask:

> "What do I remember?"

Without notes.

---

## TYPE B — CONCEPT REVISION

Review:

* definitions
* intuition
* rules
* complexity

---

## TYPE C — IMPLEMENTATION REVISION

Write the implementation again.

---

## TYPE D — PROBLEM REVISION

Re-solve representative problems.

---

## TYPE E — INTERVIEW REVISION

Explain the topic verbally.

---

# 4. REVISION PRIORITY

Not everything receives equal revision time.

### High priority

* DSA patterns
* Java fundamentals
* OOP
* collections
* SQL
* DBMS
* CN
* OS
* backend concepts
* interview questions

### Medium priority

* supporting concepts

### Low priority

* topics that are rarely used and already well understood

---

# 5. REVISION TRIGGERS

A topic should be revised when:

* you forget it
* you make a mistake
* you cannot explain it
* you cannot implement it
* you encounter a related topic
* an upcoming interview requires it

---

# 6. WEEKLY REVISION

Every week should contain some review.

Weekly review should include:

```text
Previous Java
Previous DSA
Previous SQL/core topics
Mistakes
Important patterns
Unfinished work
```

Saturday/Sunday may be used as catch-up/revision buffers.

---

# 7. MONTHLY REVISION

At larger intervals:

* review major concepts
* inspect progress
* revisit mistakes
* re-solve representative problems
* remove obsolete notes
* update progress tracking

---

# 8. REVISION AFTER FAILURE

If you repeatedly fail at the same concept:

```text
Failure
↓
Identify misconception
↓
Relearn
↓
Simplify notes
↓
Practice easier problems
↓
Return to original problem
```

Do not simply reread the same explanation repeatedly.

---

# 9. REVISION + SPACED REPETITION

---

# 10. GOLDEN RULE

> **Revision should become shorter and more active as mastery increases.**

A beginner may need explanation.

An advanced learner should need:

> "Recall → implement → solve."
